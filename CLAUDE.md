# About repo-store

## What it owns

`:8306`. Canonical registry of repositories and their detected signature — the stable, session-independent answer to "what is this repo?" (languages, frameworks, build tools, test tools) as a flat tag set. Those tags feed the bundle resolver. Boundary against forge: forge owns ephemeral session-scoped workspaces, repo-store owns durable repo identity. Wire types (`Repo`, `Deployment`, `Signature`, `PullRequest`) rendered to TypeScript by `./generate-ts.sh` as `@kayushkin/repo-store-types` (since 2026-09-18). To rename a repo or move its path, use `PUT /repos/{id}/identity` (name, path and git_remote, all required), never `POST /repos` with the new name: the POST upserts by name and would make a second row with a new id, cut off from its deploy ledger.

The variables it reads, `REPO_STORE_ADDR`, `REPO_STORE_DATA_DIR`, `REPO_STORE_PULL_REQUEST_SYNC_INTERVAL` and `REPO_STORE_GITHUB_CLI`, are declared once in `settings.go` with llm-bridge `servicesettings` (hence `replace ../llm-bridge` in `go.mod`, which makes `deploy-gate` check that tree too) and served read-only at `GET /settings`. A new variable is declared there or `TestEveryEnvironmentVariableTheServiceReadsIsDeclared` fails, and a set `REPO_STORE_` variable that nobody declared stops the service at boot; `deploy.sh` checks the running service's environment for one before it stops it. Declare nothing `Editable` while the service has no operator gate. `settings.go` defaults to `127.0.0.1:8306` and the unit says the same, because the service has no auth. Facts about this host's instance (its drop-in, which GitHub account gh uses and why not auth-store, the registry's population history) are in the noteboard note tagged `repo-store`.

It owns GitHub pull requests: no other service on the box calls GitHub for them. A background loop (`pull_request_sync.go`) reads, every `REPO_STORE_PULL_REQUEST_SYNC_INTERVAL` (default 10 minutes), the pull requests of every repo with a `github_url`, only those updated since that repo's last successful sync began (all of them the first time, or after its remote moves to another GitHub repository), into `pull_requests`, keyed (repo_id, number). A repo whose sync fails is logged as `pull-request sync of repo <id> (<name>, <url>) FAILED: …` and the others carry on; each pass ends with one summary line in `journalctl --user -u repo-store`. Read them with `GET /pull-requests?repo_id=&state=open|closed|merged|all&limit=` (`state` defaults to `open`, `limit` to 100; `closed` means closed without merging; an unknown parameter is a 400), and sync one repo now with `POST /repos/{id}/pull-requests/sync` (400 with no `github_url`, 502 when GitHub fails). It reaches GitHub through the `gh` CLI logged in under the service's HOME, named by `REPO_STORE_GITHUB_CLI` (the unit sets `%h/bin/gh`, because a user unit's PATH lacks it; the service will not start without it), and not through auth-store. There is no second way in: if gh's login lapses, every sync fails loudly until someone runs `gh auth login`. To move to an auth-store token, replace `GitHubCommandLine` rather than adding beside it.

## Where this prompt lives

These sections are stored in agent-store as a project prompt collection and rendered, with identical text, to `AGENTS.md` and `CLAUDE.md` at the root of this repo, so that whichever file a harness reads it gets the same thing. Edit them on dash `/files`, or edit either rendered file: the 15-minute scan carries the edit back into the sections and out to the other file. The host prompt keeps one row for this repo with only what an agent elsewhere needs.

## Public repository: nothing personal

This repo is meant to be public. Nothing about the user or this host goes in it — not in code, tests, comments, commit messages or this prompt: no names of people, chats, accounts or machines, home directories, personal file paths, SSH aliases or tokens. The unit file uses `%h`, never a home directory. Tests use made-up owners, aliases and paths (`example-owner`, `gh-alias`, `/srv/src/webapp`). A fact an agent here needs about this host goes in the noteboard note tagged `repo-store`.
